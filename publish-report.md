## 2. Quality Analysis

### 2.1 WARN — Lombok Declared as `implementation` Instead of `compileOnly`

**Severity:** High  
**File:** `build.gradle` lines 52–55  
**Impact:** Lombok appears as a `runtime`-scoped dependency in the generated POM

**Current configuration:**

```gradle
implementation("org.projectlombok:lombok:${project.lombokVersion}")
annotationProcessor("org.projectlombok:lombok:${project.lombokVersion}")
```

**Problem:**  
With the `java-library` plugin and `from components.java`, the `implementation` configuration maps to `runtime` scope in the published POM. This means every consumer of pgjson will transitively pull in Lombok at runtime, even though Lombok is a compile-time-only annotation processor that has zero runtime purpose.

**Recommended fix:**

```gradle
compileOnly("org.projectlombok:lombok:${project.lombokVersion}")
annotationProcessor("org.projectlombok:lombok:${project.lombokVersion}")
testCompileOnly("org.projectlombok:lombok:${project.lombokVersion}")
testAnnotationProcessor("org.projectlombok:lombok:${project.lombokVersion}")
```

## 3. Best-Practice Recommendations

### 3.1 Use Idiomatic Gradle Source/Javadoc JAR Tasks

**Priority:** Low  
**Current:** Custom `sourceJar` and `javadocJar` tasks  
**Recommendation:** Replace with the idiomatic Gradle approach:

```gradle
java {
    withSourcesJar()
    withJavadocJar()
}
```

**Benefits:**
- Automatically wires into the `maven-publish` plugin (no need for `artifact sourceJar` / `artifact javadocJar`)
- Includes resources in the sources JAR (current `sourceJar` only includes `allJava`)
- Follows Gradle conventions

### 3.2 Add Optional POM Metadata

**Priority:** Low  
**Recommendation:** Add these optional elements for richer metadata:

```gradle
pom {
    inceptionYear = '2024'
    
    organization {
        name = 'DeltaTango'
        url = 'https://github.com/deltatango'
    }
    
    issueManagement {
        system = 'GitHub Issues'
        url = 'https://github.com/deltatango/pgjson/issues'
    }
}
```

### 3.3 Bundle LICENSE in JAR META-INF

**Priority:** Low  
**Recommendation:** Add to `build.gradle`:

```gradle
jar {
    into('META-INF') {
        from 'LICENSE'
    }
}
```

### 3.4 Consider Sigstore Signatures

**Priority:** Low (future-proofing)  
**Context:** As of January 2025, Sonatype Central Portal supports Sigstore signature validation. While currently optional, it will eventually become required. PGP signatures remain the primary requirement.

### 3.5 Version Tag Consistency Check

**Priority:** Low  
**Recommendation:** Add a CI step to verify the Git tag version matches `build.gradle` version before publishing. This prevents accidental mismatches (e.g., tag `v26.3.1` but `build.gradle` says `26.2.2`).

## 5. Conclusion

**The pgjson project is ready for Maven Central publication.** All 12 mandatory Sonatype requirements are satisfied. The CI pipeline is correctly configured for tag-triggered automated releases through the OSSRH Staging API with automatic deployment finalization.

**Action required before next release:** Fix the Lombok dependency scope from `implementation` to `compileOnly` to prevent it from leaking into consumers' dependency trees. This is not a deployment blocker but is a significant quality issue for library users.
